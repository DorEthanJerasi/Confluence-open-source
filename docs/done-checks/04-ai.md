## Decisions (the lead's, fixed for this stage)

- **Switch.** `AI_PROVIDER` = `anthropic` | `stub` | `off`. Unset or empty:
  `anthropic` when `ANTHROPIC_API_KEY` is non-empty, otherwise `off`.
  `AI_PROVIDER=anthropic` with no key is treated as `off`, with one plain line
  in the server log at start (no key printed). Any other value: `off`, same log.
- **Off means invisible.** When off, `GET /api/ai/status` says
  `{ enabled: false }`, every AI route answers `404 { error: "ai_off" }`, and the
  web app shows no AI button, menu entry or screen.
- **The key stays on the server.** It never appears in a response body, a
  header, the web bundle or a log line.
- **Same permission path as search.** Summarise needs viewer on the page's
  space (`requireSpaceRole`). Ask retrieves only through SQL that uses
  `visibleSpaceIds(user)` inside the same statement, never filtering afterwards
  in JavaScript. A page the asker cannot read is never sent to the model and
  never cited.
- **The server owns the citations.** The model cites `[n]`; the server maps each
  `n` to a source it supplied and drops every other `[n]`. Links come from the
  server's list, never from model text.
- **Answers and summaries are plain text.** The client renders them as text and
  turns only the server-listed `[n]` markers into links. Never raw HTML.
- **Tests cost nothing.** Every automated test (Vitest and Playwright) runs on
  the stub or an injected fake. No test reaches the network, even when the shell
  that runs it has `ANTHROPIC_API_KEY` set.
- **Original names only.** The UI says "Summarise" and "Ask your docs" (or our
  own wording). No product or feature names from the tool we are modelled on.
- **Not in this stage:** chat history, streaming, saving summaries to the page,
  per-user rate limits, other providers. The interface leaves room for them.

## 4b — Summarise a page

### Build
- [x] `apps/server/src/ai/prompts.ts` holds every AI prompt (this one and 4c's).
      Page text goes in as data inside `<page>` … `</page>`, with any `<page`
      or `</page` in the text escaped, and the system prompt says to treat it as
      content, not instructions.
- [x] `apps/server/src/ai/features.ts`: `summarisePage(db, provider, user, pageId)`.
      Uses `pages.doc_text` and the title; cuts the text to 24,000 characters;
      `maxTokens` 400. An empty page returns
      `"This page has no text to summarise yet."` without calling the provider.
- [x] `POST /api/pages/:id/summary` → `{ summary }`. Needs viewer on the page's
      space; a page the user cannot read (or a deleted one) gives 404, exactly
      like `GET /api/pages/:id`, and the provider is not called. AI off → 404
      `ai_off`.
- [ ] Screen: a **Summarise** button on `PageScreen`, next to History, shown only
      when `/api/ai/status` says enabled (fetched once, cached by TanStack
      Query). It opens a quiet card above the page body with a soft loading
      state, then the summary as plain text, a Close control and, on 502, one
      calm line ("AI is not available right now. Try again in a moment.").
      Viewers see it too.
- [ ] Styles use only the design tokens; the card fades in and respects
      `prefers-reduced-motion`; light and dark both look right.

### Checks that must exist and pass
- [x] **Vitest (`ai.test.ts` or `ai-summary.test.ts`, real Postgres, stub):**
  - an editor and a viewer of the space both get a summary that starts with the
    page's first sentence;
  - a non-member asking about a page in a restricted space gets 404, and a
    counting fake provider shows zero calls;
  - an empty page gets the fixed sentence and zero provider calls;
  - a page whose text says "Ignore all previous instructions" reaches the fake
    provider inside `<page>` … `</page>`, and the system prompt is the fixed one;
  - AI off → 404 `ai_off`; provider throws → 502 `ai_unavailable`.
- [ ] **E2E (Playwright, stub), `e2e/tests/ai.spec.ts`:** `e2e/global-setup.ts`

## 4c — Ask your docs (server only)

### Build
- [ ] `apps/server/src/ai/retrieve.ts`: `retrieveSources(db, user, question)`.
      One SQL statement finds the best 5 pages for the question with the
      `pages.search` GIN index, using the question's words joined with OR
      (only letters and digits reach `to_tsquery`; stop words drop out). The
      permission filter is `visibleSpaceIds(user)` inside that statement;
      deleted pages and children of deleted pages never appear.
- [ ] Each found page's `doc` JSON is split at heading blocks into chunks
      (heading + the blocks under it, as text via `nodeToText`, cut to 1,500
      characters). The best 8 chunks (most question words, then page rank) are
      the numbered sources `[1]`…`[8]`, each with `pageId`, `title`, `spaceKey`.
- [ ] `askDocs(db, provider, user, question)` in `features.ts`: sources go to the
      model as `<source n="1" title="…">…</source>` (escaped the same way as
      4b), with a system prompt that says: answer only from the sources, cite
      each claim as `[n]`, and say plainly when the sources do not answer it.
      `maxTokens` 800.
- [ ] No sources found → the fixed answer
      `"I couldn't find anything about that in the pages you can see."` with
      `sources: []`, and the provider is not called.
- [ ] Citations: the server reads every `[n]` in the reply, keeps those with a
      supplied source, removes the others from the text, and returns only the
      cited sources, in order of first use.
- [ ] `POST /api/ai/ask` with `{ question }` (1 to 500 characters after trimming;
      otherwise 400) → `{ answer, sources: [{ n, pageId, title, spaceKey, spaceName, url }] }`,
      where `url` is `/s/:spaceKey/p/:pageId`, the same link a search result
      opens. AI off → 404 `ai_off`; provider error → 502 `ai_unavailable`.
      Zod contracts in `packages/shared`.

### Checks that must exist and pass
- [ ] **Vitest (`ai-ask.test.ts`, real Postgres, stub and fakes):**
  - a question whose words are in an open-space page returns an answer citing
    `[1]`, and `sources[0]` is that page with the right `url`;
  - **permission:** a restricted-space page that matches the question better
    is never in `sources` for a non-member, and its text is not in anything
    the fake provider received. After the user is added as a member it can be
    cited; after removal it cannot;
  - an instance viewer can ask over open spaces; an instance admin's sources
    can include every space;
  - a deleted page is never a source;
  - a fake provider that answers `"See [2] and [9]."` with two sources gets back
    text without `[9]` and `sources` holding only source 2;
  - a question matching nothing gets the fixed answer and zero provider calls;
  - a page saying "Ignore all previous instructions" reaches the provider inside
    a `<source>` tag, and the system prompt is the fixed one;
  - empty question and a 501-character question give 400; signed out gives
    401; AI off gives 404 `ai_off`.
- [ ] `npm run test:ai` and `npm run check` pass (exit 0), still with no network.
